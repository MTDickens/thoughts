## 0. 一句话结论 {#s0}

::: {.tip title="2026-10-09 更新：中间值改为约 $100"}
按质量安全的最快跑法（8 个单卡副本，无损 BF16）重算：每段约 33 秒，300 道约 **3.2 小时、约 $100（约 ¥730）**，一次 4 小时租期内能跑完。下面第 0–6 节是 10-08 的旧估算，保留原样。新数字见第 8 节和 [H3 加速调研](wrop-h3-nvidia-speed.md)。
:::

- 用 MiniMax 视频模型重跑 300 道题，在一台 8×B300 上大约要 **3–8 小时**（含装环境），花 **约 $100–350（约 ¥700–2,500）**，中间值约 **$170（约 ¥1,200）**。
- 用 MiniMax 官方 API 跑同样 300 道，大约 **$180–360**，不用装任何东西。两条路钱差不多。
- 如果还要用新 prompt **重训 PWM-WROP**，那是另一笔账：约 **15–50 节点小时，$480–1,600**，外加把训练代码从 Trainium 移到 GPU 的工程量。

::: {.warning title="模型名"}
“MiniMax M3” 是语言模型，不能生成视频。我按 **MiniMax H3**（论文里用的视频模型）来算。
:::

## 1. 范围和假设 {#s1}

**模型是哪个**

| 名字 | 是什么 | 能不能重跑 WROP |
|---|---|---|
| MiniMax M3 | 2026-06 发布的开源多模态**语言模型**（428B，激活 23B）。输入可以是视频，输出只有文字。 | 不能生成视频。可以用来改写 prompt，或者当自动评委。 |
| MiniMax H3（Hailuo 03） | 2026-07/08 发布的视频模型，开源权重（H3-Base，33B DiT）。论文表 1 里的 “MiniMax H3” 就是它，走 FAL API，参考生视频模式。 | 能。本文按它估算。 |

**每道题的工作量**（来自论文第 3 节、表 1、第 4.3 节）

- 输入：60 帧参考视频（2.5 秒，24 fps）+ 文字 prompt。2 道题是 90 帧输入。
- MiniMax H3 输出：1344×768、24 fps、124 帧（约 5.2 秒）。这正好是 H3 官方基准测试用的尺寸。
- 用的是 H3 的 **Ref2VA**（参考生视频）权重，不是纯文生视频。参考视频会加长序列，所以比纯文生视频慢。

**300 道题里有多少要改 prompt**

- 197 个 prompt 变体：142 个 OVER，55 个 OK。
- 我按场景脚本把 300 道考题对上 prompt：**196 道用 OVER prompt，104 道用 OK prompt**。（假设考题的 prompt 和脚本里的 prompt 一样。）
- 所以只改 OVER 的话，真正要重新生成的是 196 道。

**不在范围内**

- 只是推理（生成视频），不训练。
- 不含人工打分（Elo）的费用。像素指标（SSIM、LPIPS 等）用 CPU/单卡几分钟就能算完，可以忽略。

## 2. 每道题要多久 {#s2}

**已发布的实测数据**（SGLang 官方基准，8×B300 一台，Ulysses 8，一次一个请求，1344×768×124 帧，50 步）：

| 权重 | 精度 | 每段视频 |
|---|---|---|
| FL2VA（文生视频） | BF16 | 19.0 秒 |
| Ref2VA（参考生视频） | BF16 | 29.1 秒 |
| Ref2VA | FP8 | 27.1 秒 |

另一组数据：8×H200 上，带参考视频的 V2V 每步 2.57 秒，纯文生视频每步 0.75 秒，慢 3.4 倍。WROP 的参考视频只有 2.5 秒，所以不会慢这么多。

::: {.note title="更正（2026-10-09）"}
这张表的测试脚本发送的是 `"task":"t2va","conditions":[]`，没有参考视频。Ref2VA 两行只是用 Ref2VA 权重跑文生视频，不是参考生视频的速度。见第 8 节。
:::

**我的估算（每道题）**

| 情况 | 8×B300 一起跑一段 | 1×B300 单独跑一段 | 什么情况下会这样 |
|---|---|---|---|
| 低 | 约 25 秒 | 约 2.5–3 分钟 | 参考视频开销小，和官方 Ref2VA 数字一样 |
| 中 | 约 40 秒 | 约 5 分钟 | 2.5 秒参考视频让序列变长约 1.5 倍 |
| 高 | 约 70 秒 | 约 8–9 分钟 | 按 H200 上 V2V 的慢速比例推算 |

“1×B300” 一栏是推算：B300 有 288 GB 显存，整套权重（约 134 GiB）放得下一张卡。单卡时间 ≈ 8 卡时间 × 8 × 并行效率（0.7–0.9）。交叉检查：一张 288 GB 的 AMD MI355X 跑 209 帧要约 5 分钟，折算到 124 帧约 2–2.5 分钟，对得上“低”这一档。

**8×B300 上怎么跑最快**

1. 用 SGLang 或 vLLM-Omni 的 H3 服务，权重常驻显存。
2. **不要**指望把多个请求拼成一批。vLLM-Omni 实测：多个大请求同时跑，总吞吐不提高。
3. 不需要 CFG 并行。H3 已经做了 CFG 蒸馏，每步只算一次。
4. 要吞吐就开多个副本：8 个单卡副本，或 2 个 4 卡副本。这样比 1 个 8 卡副本多出约 10–30% 吞吐。要单段最快就用 1 个 8 卡副本。
5. FP8 只省显存，基本不省时间（29.1 → 27.1 秒）。为了和论文可比，用 BF16。
6. Cache-DiT 这类加速能快 1.3–1.4 倍，但会改变输出（SSIM 降到 0.93–0.97）。评测时不要开。

## 3. 300 道题一共多少算力 {#s3}

| 情况 | 生成本身 | 每次租用的准备时间 | 总时间（一台 8×B300） | GPU 小时 |
|---|---|---|---|---|
| 低 | 300 × 25 秒 ≈ 2.0 小时 | 约 0.5–1 小时 | 约 2.5–3 小时 | 约 20–25 |
| 中 | 300 × 40 秒 ≈ 3.3 小时 | 约 0.5–1 小时 | 约 4–4.5 小时 | 约 32–36 |
| 高 | 300 × 70 秒 ≈ 5.8 小时 | 约 1–2 小时（要租两次） | 约 7–8 小时 | 约 56–64 |

准备时间包括：下载 Ref2VA 权重（约 144 GB）、加载、预热、跑几道冒烟测试。第一次搭环境如果出问题，还会多花 1–3 小时。

::: {.warning title="两个实际限制（来自 Second Mate 拿到的学术云条款）"}
- 每次只能租 4 小时。中、高两档都可能要租两次，每次都要重新下权重。
- 工作盘只有 50 GiB，放不下 144 GB 权重。只能放在本地 NVMe 上，归还机器时会被清空。
:::

## 4. 重训 PWM-WROP：另算 {#s4}

- 只改测试 prompt，**不需要**重训任何模型。外部模型（包括 MiniMax）只是重新生成。
- PWM-WROP 用新 prompt 重新**推理** 300 道：320×192、35 步，模型 16B。估计不到 0.5 节点小时（约 $16）。前提是检查点能下载到。
- 如果还要用改写后的 prompt **重训** PWM-WROP（1.5M 条训练样本），估算如下：
  - 论文实测：一台 trn2.48xlarge 每步 5.7 秒，批量 16，每秒 12,454 token。1.5M 条按这个速度要约 150 小时（在 288×512 尺寸下）。
  - 换到 8×B300（BF16 稠密 18 PFLOPS），按 320×192 的 token 数和 20–40% 利用率粗算：约 **10–20 节点小时**训练。加上数据下载（训练集 214 GB）、视频编码和调试，约 **15–50 节点小时**。
  - 费用：**约 $480–1,600（约 ¥3,400–11,000）**。
  - 最大的成本是工程：PWM 训练代码是为 Trainium 写的，要移到 GPU 上。
  - 这一条比重跑测试大 5–10 倍，不要和上面的数字混在一起。

## 5. 费用 {#s5}

价格来源：National Compute 公共研究（.edu）价，B300 每卡每小时 $4，整台 8 卡 **$32/小时**。新用户有 $100 赠送额度。汇率按 1 美元 ≈ 7.1 元粗算（未核实当天汇率）。

| 方案 | 节点小时 | 美元 | 人民币 |
|---|---|---|---|
| 重跑 300 道，低 | 约 2.5–3 | 约 $80–100 | 约 ¥570–700 |
| 重跑 300 道，中 | 约 4–4.5 | 约 $130–150 | 约 ¥900–1,050 |
| 重跑 300 道，高 | 约 7–8 | 约 $220–260 | 约 ¥1,600–1,800 |
| 加上第一次搭环境的调试 | +1–3 | +$32–96 | +¥230–680 |
| **对照：官方 API 跑 300 道** | 0 | 约 $180（MiniMax 官方 768P）到 $360（fal 标价） | 约 ¥1,300–2,600 |
| 重训 PWM-WROP（另算） | 约 15–50 | 约 $480–1,600 | 约 ¥3,400–11,000 |

API 怎么算：MiniMax 官方 768P 输出 $0.08/秒，输入参考视频按同价计秒。每道题约 5 秒输出 + 2.5 秒输入 ≈ $0.60。fal 页面上 768p 标价 $0.16/秒，各家标价不一致。

## 6. 敏感性：跑多少题 {#s6}

| 方案 | 生成数量 | 节点小时（低–高） | 美元（含一次准备） |
|---|---|---|---|
| 只看 OK 题（104 道，prompt 不变） | 0（直接用论文发布的输出）或 104 | 0 或 约 1.2–3 | $0 或 约 $40–100 |
| 只重跑 OVER 题（196 道） | 196 | 约 1.8–4.8 | 约 $60–160 |
| 全部 300 道 | 300 | 约 2.5–8 | 约 $80–260 |
| **推荐：新旧 prompt 各跑 300 道** | 600 | 约 5–13 | 约 $160–420 |
| 再乘 3 个随机种子 | ×3 | ×3 | ×3 |
| 只用一部分训练题（例如 10%）重训 PWM-WROP | — | 约 2–5（训练）+ 工程 | 约 $60–160 + 工程 |

::: {.tip title="为什么推荐新旧 prompt 都跑"}
本地 H3-Base 和论文用的 FAL 托管版不完全一样（托管版可能有不同版本或额外处理）。如果只用本地跑新 prompt，再拿去和论文里的旧分数比，你分不清分数变化来自 prompt，还是来自换了跑法。同一套环境里新旧都跑一遍，差别才只来自 prompt。
:::

## 7. 最大的不确定因素 {#s7}

1. **模型是谁**。我把 “M3” 当成笔误，按 H3 算。如果你本意是用 M3 改写 prompt 或当评委：改写 142 条 prompt 走 API 只要几美分到几美元；自己部署 M3 要约 444 GB 权重，不值得。
2. **API 还是本地**。本地只能跑 H3-Base（768p）。官方的 Context-IR 和 2K 重生成只在 API 上有。论文输出是 1344×768，和 768p 本地一致，但不保证完全相同。
3. **每道题实际要多久**。带 2.5 秒参考视频的 Ref2VA 在 B300 上没有公开数字。估计 25–70 秒，差约 3 倍，这是总时间最大的变量。
4. **许可证地域**。H3 社区许可证不覆盖美国、欧盟、英国、韩国，这些地方要另外授权。National Compute 机房在哪里，我不知道。如果在美国，本地部署有许可证问题，只能走 API。
5. **评测脚本没公开**。论文的推理脚本（输入补帧、输出裁剪、ffprobe 检查）没有发布，要自己重写。
6. **考题 prompt 和脚本 prompt 是否一样**。196/104 的划分基于这个假设，没有逐条核对考题文件。
7. **人工打分**。如果要重做 Elo，人工费用和时间可能比 GPU 贵，本文没算。

## 8. NVIDIA 优化路径（2026-10-09 补充） {#s8}

完整内容在 [H3 加速调研](wrop-h3-nvidia-speed.md)。要点：

- 质量安全的方案：SGLang 无损 BF16（或 NVIDIA 的稠密 50 步），开 8 个单卡副本。T2VA 约 16 秒/段（有效吞吐）。
- WROP 带 2.5 秒视频参考，推算约慢 2 倍：**每段约 33 秒**。
- **300 道：约 3.2 小时，约 $100（约 ¥730）**，一次 4 小时租期内能跑完。保守约 7 小时、约 $220。第一次搭环境另加 $32–96。
- 新旧 prompt 各跑 300 道（中间值）：约 6.5 小时，约 $200。

::: {.warning title="Sol-H3：质量未验证"}
你记得的 NVIDIA 方案是 **Sol-H3**（NVIDIA Research）：8×B300 上 1.653 秒生成 5 秒视频。它用了 4 步蒸馏、稀疏注意力和 INT8/FP8 传输，会改变输出，公开材料没有和原版的质量对比，而且只测了文生视频。所以不用于评测成本。其他激进加速（蒸馏、稀疏、缓存、量化）都列在调研页第 4 节。
:::
